# Анализ SAST (Semgrep)

## Реальные уязвимости

1. **SQL-инъекция** (`CourseService.searchByTitle`): строка SQL собирается конкатенацией с вводом пользователя. Устранение: `PreparedStatement`, `JdbcTemplate.query` с параметрами `?`, или метод репозитория `findByTitle`.

2. **SSRF** (`ProxyController`): параметр `targetUrl` передаётся в `RestTemplate` без ограничения. Устранение: белый список хостов/схем, запрет file:// и внутренних IP, разбор URL и проверка.

3. **XXE** (`XmlController`, dom4j `SAXReader`): разбор XML из тела запроса без отключения внешних сущностей. Устранение: `reader.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true)` и родственные флаги, либо безопасный парсер по настройкам для Java XML.

4. **Хранение паролей в открытом виде** (`User`, `data.sql`, `AuthController`): пароли сравниваются и хранятся как plaintext. Устранение: BCrypt/Argon2, не логировать пароли.

5. **Привилегированная регистрация** (`login.html` / `AuthController`): пользователь может задать роль в форме регистрации (демо A04). Устранение: фиксированная роль для саморегистрации, роли только у администратора.

6. **Раскрытие информации** (`application.yaml`, `server.error.include-stacktrace: ALWAYS`): полные трассировки в ответах об ошибках. Устранение: для prod `NEVER` или `ON_PARAM`, единый безопасный формат ошибок.

## Ложные срабатывания (типовые для Semgrep / Java Spring)

- Обращение к БД через JPA/`JdbcTemplate` в легитимных местах без пользовательского ввода в запросе.
- Жёстко заданные URL или демо-данные в `data.sql`, если правило не различает тестовые сценарии.
- Использование Thymeleaf с экранированием по умолчанию: часть правил может помечать вывод в шаблонах как XSS без учёта контекста `th:text`.
- Зависимость `dom4j` старой версии: предупреждения по CVE без учёта фактического кода вызова.

## Рекомендации по устранению (кратко)

- Ввести слой DTO и валидацию входных данных; не использовать строковую склейку SQL.
- Для HTTP-клиента к произвольным URL — явная политика доверенных назначений.
- Для XML — безопасный профиль парсера; по возможности отказ от устаревшего dom4j 1.x.
- Пароли — только хеш с солью; политика ролей на сервере.
- Настройки ошибок и actuator endpoints — ограничить для production.
